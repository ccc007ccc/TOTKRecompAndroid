并在 TotK 1.4.3 + Turnip/Adreno 8xx 上默认开启两条路径；本页保留当时单独优化和默认关闭的结论。

## 已确认的数据流

TotK 1.4.3 的观测调用点为 `0x7000133c28`：复制 304 字节，写入一个 880 字节常量缓冲区的
末尾 304 字节。该函数通过反射查找成员 `p_dynamic_debug3`；后续多个顶点/片元着色器实际使用
复制范围，不能因为名称带 `debug` 就跳过更新。诊断记录调用点、复制范围、绑定阶段/槽位、
着色器地址，以及绑定长度和实际上传长度，不把每个绑定都当作实际使用。

已有直接 UBO 实验验证此缓冲区满足主堆放置、对齐、长度和无已知 inline 更新的条件。
之前仍在绘制预检查中按整段 UBO 等待，因此启用直接绑定本身没有解除这处等待。
目前没有证明源数据只由 CPU 产生，不能把游戏复制替换为提前 CPU memcpy。

## 同步实现

- 对与待完成复制目标重叠、符合直接绑定条件的 UBO，在绘制/计算预检查中冻结描述符选择。
  绑定时使用同一决定，避免命令录制线程此后标记 inline 更新，导致临时退回读取未完成数据的 CPU 上传。
- 使用独立、最多 64 项的 GPU 读取记录。预检查保留稳定索引，真正绑定时记录其提交序号。
  复制完成不等于后续绘制完成；CPU 更新须保护整个直接绑定范围，包括没有被复制的前缀。
- 纹理句柄按实际 4 字节预检查；片元槽 0 的全屏填充检测保留前 12 字节检查；顶点槽 0/5 的
  宽屏 CPU 使用、存储缓冲区、诊断、提交快照及不支持的映射仍使用保守路径。
- 跟踪表满时回退原 CPU 读取预检查。等待仍发生在取得 command buffer/render pass 之前，
  描述符绑定不提交、不等待。游戏退出/重启清理读取记录与冻结选择。
- 每条命令的 pending 查询不再调用 `vkGetSemaphoreCounterValue`；真正遇到依赖、新复制或表容量压力时才查询完成序号。
  提交时复用纹理资源回收已查询的完成序号，及时清理复制记录，避免已完成的复制继续触发整套绘制预检查。
- 捕获的线宽/点大小等标量状态不再触发全内存预检查。纹理间复制只检查可能上传的两侧纹理；
  `SignalEvent` 只保护事件对象首字和指向的 4 字节存储。后者在当前执行器仍是已知未实现命令，
  本轮没有把预检查修正宣称为完整事件协议实现；其他未知命令继续保守等待。

上述路径复用现有异步复制和直接 UBO 的资格检查。是否启用仍由 `LARECOMP_VK_ASYNC_BUFFER_COPY`
控制，不依赖硬编码 guest 缓冲地址，也不修改生成游戏库或制作单独 Mod 包。

## 验证

`tools/test_buffer_copy.sh` 的 ASan/UBSan 回归包含实际生产预检查、绑定与复制 helper，使用延迟完成的模拟 GPU，覆盖：
复制完成后仍在途的 UBO 读取、前缀 CPU 写入、预检查后 inline 标记、纹理句柄 CPU 读取、跨提交索引保留、
跟踪容量回退、范围/对齐、快照/诊断回退和等待失败。上传缓存与点尺寸驱动常量回归亦通过。

手机测试使用 PJZ110 / Adreno 830 / Turnip、Release / snapdragon-8elite / perftest，
复用 `GAMELIB_ID=993c0a5c82dc5099` 的 O3 游戏库。固定已有草地存档、设置种子、60 FPS 目标，
就绪后运行 15 秒自动退出，不暂停、不截图；诊断和普通 FPS 对照分别记录。

调查中第一版直接绑定将绘制预检查耗时约从 3.96 降至 1.98 ms/帧，但 buffer-copy 等待仍约
1.8 ms/帧，迁移到了标量状态命令。第二版越过这些命令后，等待又迁移到 `SignalEvent` 的
全内存兜底，约 8.50 ms/帧；同时 `SyncWait` 减少到约 0.27 ms/帧。这是等待位置变化，
不能把某一个分类的下降单独当作收益。第二版测量时手机转为充电，电池温度约 38.5°C，
也不能用它的 24.36 FPS 直接对比此前未充电的 26.20 FPS。

## 等待链路与普通帧率

消除事件通知的全内存兜底后，`direct3-trace` 有效统计窗口 307 帧中没有 buffer-copy CPU 等待，
`SyncWait` 约 5.31 ms/帧，GPU 约 24.88 ms/帧。该版普通 A–B–A 使用同一 APK
`3ddc768e224d59264de1e8f7ea67a4faa4fcd1fafc52860755c6486107d32034`，无 profiling、保持充电：

| 运行 | 异步复制 | FPS | p95 (ms) | 电池温度前→后 |
| --- | --- | ---: | ---: | --- |
| `ordinary-a1` | 关 | 28.33 | 48.11 | 39.6→40.0°C |
| `ordinary-b1` | 开 | 29.94 | 43.71 | 40.3→40.4°C |
| `ordinary-a2` | 关 | 29.65 | 47.00 | 40.7→40.8°C |

开启时比第一次关闭高约 5.7%，但比第二次关闭只高约 1.0%。因此不以第一次差值宣称稳定提升。

最终版再复用现有提交回收的完成序号。`final-trace` 完整统计窗口 371 帧，复制依赖等待仍为 0，
绘制预检查约 2.27 ms/帧（上一版约 4.20），GPU 约 25.28 ms/帧、`SyncWait` 约 5.45 ms/帧。
这些统计含诊断开销，温度也不同；只能确认等待类别和扫描开销的变化，不能等同普通帧率收益。

不把短测扩大为稳定百分比或其他场景结论。**异步复制与共享映射继续默认关闭**。
原始证据、每次启动身份及汇总保留于上述私有目录；实际安装的是最终 Release / 8 Elite / perftest APK。

本轮确认并移除了复制结果需要经过 CPU 的额外等待，实际 GPU 工作仍约 25 ms/帧。
后续重点应转向 GPU 多目标绘制/着色器成本、游戏帧调度，以及移动/割草路线的长程正确性；
不能继续删掉真正的帧同步来追求表面帧率。独立 Mod 包和重新生成整套游戏 C 都不是本轮必需条件，
本次改动在 NVN/Vulkan 适配层完成。
