## 编译卡顿与预热

旧包标题准备命中 734 个模块，约 0.286 秒；已有 1,662 条管线配方，8 个后台 worker，最终领用 1,421 条。
新包第一次因身份拆分重新核验准备结果：703 个请求、1,113 个源码请求、908 个模块，标题准备约 7.505 秒。
旧设备配方身份不符被忽略，导入 192 条计算种子，4 个 worker；加载门禁 15 秒结束时 prepared=82、pending=110，
随后 192 条全部完成，但 runtime reused=0。种子创建成功并不保证对应运行时实际状态会命中。

新包重复启动读取已积累的 1,618 条管线并完成准备，runtime reused=1,420。后台仍有大量译码：
第一次结束 translated=13,589 / request-cache reused=62；重复 translated=8,557 / reused=12,960。
启动时堆路径变化会重启后台准备。这些数字没有证明后台准备已消除游玩负载；单次关闭预热也未显示收益，暂不改默认。

新包第一次转视角启动附近记录 max=1,137 ms、compile=848、waited=1,802 ms；重复 max=541 ms、compile=375、waited=1,111 ms。
这些窗口结束帧在正式采样首帧之前，不能加入表中 p95，也不能用表中 p95 掩盖启动阶段长帧。
`compile` 是程序/管线构建计数，不能当作 shaderc 调用次数；无 `[shader-runtime] compiling` 也不等于没有接口译码、
Vulkan 模块创建或驱动管线工作。草地普通窗口仍在约 17–26 FPS 间波动，尚未证明固定 20 帧锁或首次落水因果关系。

## 地下开场与内部间隔

另选完整种子的 slot 1（此前已核验的海拉鲁城堡地下开场），默认开启 shader/pipeline 预热、60 秒持续转视角，
额外每 120 次时钟更新记录内部间隔。结果 27.536 FPS、p95 47.041 ms，1,653 帧，区间 847–2499，运行时正常退出。
电池温度 39.4→40.1°C，Thermal Status 2→3，仍在充电。这属于带轻量间隔日志的较长场景测量。

中前段部分窗口约 35 FPS，后段约 22–25 FPS；当时实时 compile 计数已接近零，但后台仍在工作，结束累计
request-cache reused=21,383、translated=13,058，已准备管线领用 497。日志中 target 始终为 60，已记录的间隔均为
`1→1` 或 `2→1`，没有观察到 `3` 或强制回退到间隔 3。关闭游戏后温控状态读回降到 2。
不能从这一轮确定下降来自后台译码、渲染/资源等待、温控或游戏另一条逻辑，也不能将它标为落水复现。
该存档是地下开场，尚不能替代用户可能指的地底大地图。

降温后补一轮独立等待诊断：同一 slot 1、30 秒转视角，关闭 shader/pipeline 预热、开启 timing-trace（自动 profile）
和相同轻量内部间隔日志。33.074 FPS、p95 36.062 ms，993 帧，区间 808–1800；电池 40.0→39.7°C、Thermal Status 2→2。
正常退出、skipped=0。它的时长、热状态、缓存与诊断开销都不同，不能拿 33.074/27.536 的比值宣称关闭预热的收益。

只统计完全落在采样内的 931 帧窗口：

| 诊断项 | 平均 ms/帧 | 含义 |
| --- | ---: | --- |
| timeline 等待 | 13.443 | 等待 GPU 同步完成，窗口均值 12.196–14.413 |
| frame-limit 等待 | 0.000104 | 运行时目标限帧等待，单次最大 0.005 ms |
| translation 等待 | 0.317 | `vk_async_wait_id` 等待 NVN 渲染请求完成，不是 Maxwell 着色器译码总耗时 |
| present 调用 | 0.514 | 呈现调用墙钟 |
| submit 调用 | 0.365 | GPU 提交调用墙钟 |

相同窗口的原有 profiling 汇总：GPU 时间戳片段约 23.526 ms/帧，NVN 执行墙钟约 12.380 ms/帧，
描述符驱动写入约 0.272 ms/帧、cbuf 相关计时约 0.910 ms/帧。墙钟可以包含等待，CPU/GPU 和各子项可能重叠，不能相加推算 FPS。
正常策略冻结游戏动态分辨率计数器，`gpu-pairs` 的配对数为 0，因此没有该计数器的有效配对耗时；不能把它打印的零当作 GPU 无工作。
本轮依据来自独立 GPU profiling 时间戳与等待计时，完整聚合分别保存在私有 `render-summary.json`、`wait-summary.json`。
内部间隔仍为 1。后续应进一步定位 GPU/资源同步等待，并记录前台命中与后台译码实际成本；现有证据不足以确定落水回退的根因。
