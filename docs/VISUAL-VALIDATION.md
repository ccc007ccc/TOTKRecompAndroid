# 2026-10-29 画面复现与验收

本轮从 `15eb0c1` 继续，优先处理有明确对照的自动读档加载背景黑底，并复查旧草地存档。
设备为一加 13 / PJZ110 / Adreno 830 / Banner Turnip。所有构建、测试和 ADB 均在 `dev`。
草地原存档只读克隆到 perftest 的独立会话；普通应用未安装或启停。

## 自动读档加载背景

当前基线 APK `1edf207cca9345e808982720ce822098bea2574056aa3daf518e500fbf1afbe3` 可重复出现：
加载页右侧浅色面板正常，左侧应有的灰褐格线变成纯黑。相同 APK 走正常菜单确认流程，格线恢复。
首次取图因诊断目录缺少 `build/` 失败，不计为有效证据；补建任务私有目录后的捕获有效。

旧 `test_boot_patch` 将 `NormalTitle.140.module` 的入口 11 改成 44，直接进入确认后的分支。
这省略了菜单及其按钮确认过程中的状态更新。仅补回几个菜单初始化节点的临时实验仍然黑，未合入。
本轮保留完整标题/列表/确认流程，自动确认菜单，仅在私有 `OnLoadGameSaveData.module` 副本中固定四处存档索引。
不修改渲染器、着色器数值或游戏库。

自动按键在**成功读取当前测试存档副本中所选槽位的 `progress.sav`** 时停止，早于进入游戏场景。
不能用 `OnLoadGameSaveData.module` 被读取作为停止条件：该资源在第 0 帧就被预加载，原型因此停在标题页；
这个失败版本没有合入。最终检查也排除了 caption、其他槽位、原存档、同名前缀目录和零字节/失败读取。
零字节/失败读取由文件服务调用点过滤，其余条件由会话入口检查。

最终 APK `e5772cb8739bcbae2ab699db2910cd00649d8a2c04abf5d6574a09c28deeed8b` 中：

- 指定 slot 0 的加载页恢复格线，自动输入在第 577 帧停止。
- 选取避开文字和应用浮层的 856×591 背景区域，基线 RGB 均值为 `(0,0,0)`；
  修复后为 `(57.86,47.82,43.79)`，RGB 字节比较相等，`ImageChops.difference` 没有非零区域，
  确认逐像素与正常菜单流程的同一区域一致。
- 标准控制器没有额外传 `LARECOMP_TEST_AUTOLOAD`，仍能加载所选草地存档，
  就绪后完成 309 帧 / 15.025 秒并由运行时自行退出；自动输入在第 638 帧停止，就绪在第 1170 帧。
  20.57 FPS 是该草地场景本轮短测结果，不与旧裸岩悬崖场景比较性能。

这里修复的是自动测试路径的加载背景。历史 UI 局部消失和空岛单帧大面积变黑没有据此宣称解决。
菜单确认阶段多走了正常 UI 流程，测量起点仍是场景就绪后的连续采样。

## 草地短线复查

使用此前报告草消失的私有存档副本，固定 slot 0 和 60 FPS 目标：

- 第 1600 帧轻量抓取：草地、树木及角色可见。
- 从第 1630 帧向前移动 120 帧。
- 第 1820 帧轻量抓取：角色已下台阶，沿路草仍可见；第 2000 帧保存最终窗口后自动退出。

两次捕获分别约 3.98 / 4.55 MB，带阶段图、绘制记录、着色器和常量输入。
这段路线未复现草消失，不能据此说草问题已修好，也不构成跨区域加载或长期玩法验收。
