| 项目 | 本轮实现 | 验收 |

| 完整准备门禁 | `full.receipt` 保存成功队列的准确源码键集合；共用收据解析器逐项调用正式缓存解码器，连同字典依赖验证。UI 只查记录，后台任务可取消并报告进度；启动时加载设置后重新检查 | 实际编译/派生缓存覆盖整目录删除、模块损坏、缺失字典、配置变化、坏收据和取消 |

| 异步 buffer-copy | 接入原本未提交的 GPU 复制、在途源/目标保护、命令前检查和完成序号；CPU 回退复制也发送相同资源失效通知；快照路径继续使用捕获的数据 | 链式复制、CPU 可见性、源覆盖、重叠回退、队列压力及锁顺序回归通过；手机验收见下文 |

`vk_shader_game_ready` 是工具/后台 setup 使用的完整阻塞审计入口。
UI 用 `vk_shader_game_has_receipt` 判断有无当前记录，用 `vk_shader_check_*` 查询独立检查任务。
旧 `game/.shaders-ready` 不再放行启动，也不自动转换为新收据，因为它没有记录可验证的模块集合。
没有新收据时需要重新准备，或保持默认允许运行时编译。

代码写入失效遵循 NVN 的同步契约：调用方先等待在途使用，再重新绑定或发送映射写入通知。
任意线程未同步地修改指令内存没有保证。旧代次对象在本次游戏期间保留，重启时统一释放；
本轮不实现运行中按容量淘汰程序，也不宣称同一次无限长会话的资源用量恒定。

完整准备仍是启动前的显式任务，共用翻译锁保护全局配置；不会作为游戏运行中的后台全库服务使用。
模块清单完整不等于所有运行时组合已经覆盖，默认回退编译继续开启。

## 后续独立工作

以下是四类功能适配，不纳入这次六项收尾，也不是恢复历史全量优化的指令：

1. 条件纹理句柄和动态描述符数据流。
