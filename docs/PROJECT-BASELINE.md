## 着色器线

正式实现与证据见 [SHADER-BALANCED.md](SHADER-BALANCED.md)。最新方向已替代早期“全部提前展开/运行中禁止编译”：

- 手机直接读取自己的游戏输入，缓存优先；Android 默认 FP32，保留整数双精度选项。
- 标题准备、后台准备、运行时缺失编译、基于已观察状态的管线预热默认开启；均保留相应控制入口。
- 上游共享清单复用 MacNativeGames 原版工具，原始键和元数据摘要复用 D2R Mobile。
- 28,634 个当前版本输入的 FP32 翻译已验收。这个数字是输入数量，不是全部运行时变体覆盖。
- 标题 875 个源码请求对应 734 个 SPIR-V；旧独立手机检查首次约 6.28 秒、校验复用约 0.18 秒。
  后续完整应用也有标题复用、记录落盘和固定场景启动证据；这些不同运行不可混成同一性能对照。
- 准备记录已迁到应用可写缓存目录。单项请求映射允许取消后续用，使用前继续验证真正的 SPIR-V。
  后台先最近状态，再补本版本 257 个计算输入默认 seed，然后共享清单。
- 普通绘制/计算默认等待所需程序和管线；旧异步跳过仅诊断。正常与预热共用 `pipeline_state.c`。
- 稳定 `SHADER_CACHE_ID` 与构建/配方身份分离；旧缓存按审核白名单和准确内容键读取。
  718,504 份旧缓存可读不等于当前请求命中；既有 GLSL 改动导致当时标题/共享清单实际旧键命中为零。

用户暂停这条线时，最后的第二存档场景已有两轮自动读档/15 秒退出与管线复用记录，
对话报告第二轮复用 1,301 条管线、缺失/失败为零；两轮 FPS 不同，不能推断一般性能收益。
全冷缓存默认计算 seed 代价、跨区域路线、完整画面和长期行为仍未验收。
旧 2,798,003 候选长任务已停止，约 63.625% 的阶段进度不是完成；不恢复该任务或删除其缓存。

## 共享内存与复制同步线

入口与历史测量见 [PHONE-PERFORMANCE.md](PHONE-PERFORMANCE.md) 和 [EDEN-INTEGRATION.md](EDEN-INTEGRATION.md)。

- 原有共享游戏堆约 2120 MiB，但当时大量顶点位于堆外，每帧重复复制约 19.09 MiB。
  这是被分类的复制字节，不是全部 CPU 开销。CPU 渲染墙钟约 26.09 ms、GPU 约 26.85 ms 会重叠，不能相加。
- `shared_memory.c` 已接入 alias 区物理分配、Vulkan placed mapping、guest direct lookup 和复位。
  主机并发/局部释放测试以及手机短测有证据；有一轮顶点复制降至约 0.5 MiB/帧。
- 初版局部释放整块重新映射导致另一 CPU 线程崩溃，现改为保留存活映射并登记逻辑页。
  不得恢复“先 unmap 再恢复邻页”的做法。
- `buffer_copy.c` 已接入 GPU 复制、完成序号、CPU 消费/写入保护、在途源保护和纹理通知，
  不再停留在会话中途“文件已写但未集成”的状态。仍为默认关闭的实验路径。
- 一次加载失败是 APK 漏选 8 Elite profile，与原有 O3 游戏库不匹配。修正档位后仍发现真实死锁：
  纹理对象锁与等待渲染队列形成环。后续通过渲染线程纹理登记表通知修复，并增加锁顺序回归。
- 会话末尾报告两项同时打开后可以自动读档、测量和退出；同 APK 分别关开对照仍在进行，
  没有完整收尾的收益结论。默认仍为 `LARECOMP_VK_SHARED_ALIAS=0`、`LARECOMP_VK_ASYNC_BUFFER_COPY=0`。

历史原始证据在本机 `.work/totk-port/memory-bottleneck-20261029/`、`shared-memory-opt-20261029/`。
不能把较早性能章节中的“尚未实现”当作当前源码状态，也不能把最新短测当作完整优化验收。
映射 footprint/驱动分配上限、广泛在途访问、GPU 写回到 CPU 的完整语义、长期玩法与收益仍需专项验证。
