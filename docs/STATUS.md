## 本轮画面修复已确认

run40 补齐 `SetRenderEnable` 与 `SetRenderEnableConditional`，在命令执行时比较两个 NVNcounterData 的
64 位计数值，按结果跳过绘制及颜色／深度清除。时间戳字段不参与比较，状态和计数器报告仍正常执行。

修复前，bloom 放大时错误执行了本应跳过的清除：在 80×45 图像中清除 40×22 区域，可逐像素复现故障。
修复后，1000／1001 帧共跳过 117 次颜色清除和 28 次深度清除，最终 mip 左上区域恢复有效内容。
用户对针对光晕截断与场景闪烁的本轮实机版本回复 **“修好了”**。当前测试场景的画面修复已确认。

## 后续验收

- 草偶尔消失在Performance Test与普通版都出现，之后也曾恢复；用户要求先提交推送、后续再修。旧的线性纹理行距修复仍保留，新增顶点采样量化默认关闭，尚无证据确认草消失的根因。
- 自动测试读档可出现加载格线背景纯黑，用户确认同一测试版手动读档正常，已决定暂不处理。此限制与下述历史UI局部闪烁分别记录。
- 用户样本中的加载 UI 局部消失、空岛单帧大面积变黑尚未修复。蓝色出生圆盘黑块已通过纹理布局修正消除，不能据此推断前两类问题也已解决。抓取的两个按钮默认提供轻量阶段图／状态诊断，完整回放为高级选项，见 [测试指南](TESTING.md#手机本地闪屏抓取)。
- 更广泛场景、普通阴影、透明效果与长时间稳定性仍需覆盖，当前确认不能扩展到所有游戏内容和设备。
- 某些视角曾出现未实现的顶点 `DMUL` 指令；本次未处理，也未证明其与已修复故障有关。
- 其他音频场景、尚未观察到的效果类型、输入流程、存档事务／崩溃恢复和性能仍待验收。
  游戏已产生可读取的自动存档，但 `IFileSystem::Commit` 仍为占位。
- 条件渲染沿用现有 ReportCounter 的 CPU 计数值与 SAMPLES_PASSED 回退，没有增加真实硬件遮挡查询。
- ReadTexels 本轮实现覆盖 CPU 纹理存储，GPU 写入后的失效／回读仍未补齐。
- 运行时错误弹窗关闭后保留失败线程，并不恢复失败调用；依赖该线程的游戏功能仍可能停止。

## 构建与同步

应用开发版本为 `0.1.0-totk-dev`，它与游戏版本 1.4.3、上游应用版本是不同编号。
基础已合并上游 `ef7a306` / `v0.1.11-beta`；本分支另审阅至 `5675618197` / `v0.2.2-beta` 并选择性适配，
合入两笔tib-kpl运行时修复，具体来源、已整合行为和待验收项见 [上游整合](UPSTREAM-INTEGRATION.md)。
性能与帧率适配分支已合入 `main`，后续测试与修复直接在 `main` 进行。

最近已验收云层修复的版本为 run50，保留条件渲染、纹理读取、压缩尾块、错误弹窗、音频、水面反射和空岛细条修复，使用 Banner Turnip。
定向对照设置 `LARECOMP_GAME_DYNRES=1`，
保留合并前的游戏动态分辨率行为；本轮不是对上游新默认计数器策略的单独验收。
上述早期渲染记录使用全部O0游戏库。随后O1与全O3/ThinLTO、8 Elite库均已完成实机短测；
两轮60档样本的温度与充电条件不同，不能推断O3带来收益或回退。按用户要求不重测，保留原始数据，见 [手机性能测试](PHONE-PERFORMANCE.md)。

## 保留的未适配功能

BOTW/LAS 游戏地址、菜单／事件和超宽屏策略、端侧完整编译流程与 Zepp 地图不能直接用于 TOTK。
本分支的TotK四档计时采用单独核验的1.4.3实现。端侧BuildService与编译参数已适配，完整手机编译尚未验收；
当前已验证路径仍为电脑生成四模块游戏库，再通过 APK 部署。
上游新增的 RomFS 文件数量检查只列出 BOTW 版本，不构成 TOTK 资源完整性验收；本项目以准备工具的
输入身份、RomFS 边界及部署清单检查为准。
