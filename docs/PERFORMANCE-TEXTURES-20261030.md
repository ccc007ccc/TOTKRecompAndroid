# 2026-10-30：纹理排布转换与变化检测

目标继续是真实 2× / 60 FPS，包含持续转视角。用户已要求推进纹理写跟踪、描述符更新与独立 Vulkan 工作线程，
并把 BC/ASTC 的 GPU 处理提前。前期 UBWC、纹理大小缓存及负结果见 [多方向性能记录](PERFORMANCE-2X60-20261029.md)。

## 已查证的负载

一加 13 / Adreno 830 / Banner Turnip `v27.0.0-20261025-r5-A8xx` 实际报告 BC、ASTC 支持，
上传追踪中 `native` 有数据，而 `bc-cpu`、`astc-cpu` 均为零。压缩块已经交给硬件采样解码；
剩余 CPU 纹理工作是 Tegra block-linear 排布转线性行，以及上传前的变化检测。

5120×5120、7 mips 的 BC4 图集约 17 MiB，位于 CPU_CACHED 内存池，已有 WriteTexels、FlushTexels 和
FlushMappedRange 通知。旧路径在一次变化后永久标记 dynamic，即使之后每次写入都有通知，也每帧全量哈希。
实测约每两秒检查 0.8 GiB、没有变化。以前新增诊断保存对象指针的崩溃已改为复制描述值；主堆页保护实验的
loading SIGSEGV 仍是独立待调查项，尚未证明可用，不能把崩溃归因于用户测量结束后重新打开游戏。

## 本轮实现

`deswizzle.c` 的 compute 上传保留 BC/ASTC 压缩块。CPU 按上传时刻顺序复制 block-linear 输入到 transient 快照，
GPU 转为线性块行，再由原上传路径复制到图像。源和输出由已有提交序号保留至 GPU 完成，避免 GPU 延迟读取
可能被游戏改写或复用的 guest 内存。此方案仍有 CPU 快照复制，不能称零拷贝。

设备范围/对齐/派发上限与 32 位地址算术不满足时回退 CPU；RGB8 扩展、线性纹理与 CPU 贴图修改保留原路径。
compute 写入到 transfer 读取之间有屏障，部分初始化失败释放资源；reset 在渲染队列排空、GPU idle 后回收管线和布局。
内置着色器进入既有准备链路，源头文件参与 SHADER_BUILD_ID，不改游戏库 ABI 或伪造配套库身份。

通知优化只让 CPU_CACHED 池中**带正式通知**的变化保持原静态策略；无通知变化、非缓存池、已有 dynamic 和
线性动态纹理保留保守检查。现有抽样和周期校验仍保留，未宣称获得通用页面写跟踪。

| 对照开关 | 当前默认 | 含义 |
| --- | --- | --- |
| `LARECOMP_TEXTURE_FLUSH_TRACKING=0\|1` | 关，实机验收后决定 | CPU_CACHED 正式写通知不永久触发逐帧全量哈希 |
| `LARECOMP_VK_GPU_DETILE=0\|1` | 关，实机验收后决定 | GPU 排布转换与 CPU 回退 |
| `LARECOMP_TEXTURE_TRACE=1` | 关，仅诊断 | 记录变化检查、native/CPU 解码与排布转换的 CPU 墙钟 |

`[texture-layout] gpu-snapshot-record` 的时间包含 CPU 快照与命令录制，**不是 GPU 执行时间**；
`cpu-deswizzle` 对应 CPU 转换路径。诊断结果另记账，不当作默认性能成绩。

## 验证与实机进度

真实桌面 Vulkan 测试通过 128 个层级，逐字节覆盖 BC/ASTC 块布局、mip/数组/3D、大图集和受限派发，
并验证提交前源改写/释放、初始化失败清理、边界、重复 reset；同步验证没有警告或错误。
写通知策略 ASan/UBSan 回归通过，同时验证关闭开关恢复旧行为。着色器运行时、纹理通知与注册回归通过。
命令与覆盖范围见 [测试指南](TESTING.md)。

Release / Snapdragon 8 Elite / perftest 比较包构建并通过诊断隔离审计；GAMELIB_ID 仍为 `993c0a5c82dc5099`，
