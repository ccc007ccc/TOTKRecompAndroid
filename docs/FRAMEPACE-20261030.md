# 2026-10-30：游戏间隔回退与上游帧率适配

用户在 Performance Test、60 帧档下反馈：正常游玩开始帧数较高，首次落水或其他卡顿后可能变成约 20 帧，
有时又恢复。1× 分辨率本身没有设置 20 帧上限的逻辑。本轮检查游戏帧率控制器、NVN 窗口状态与运行时计时的一致性；
原目标仍是真实 **2× / 60 FPS，包含转视角**，本轮 1× 对照仅用于调查反馈。

## 上游审核

固定 [mamcjr/TOTKRecompAndroid](https://github.com/mamcjr/TOTKRecompAndroid) 快照
`cc4f134`，帧率实现来自 [da06d5a7f3fb1378eeefbcb13dc2276096a1aebc](https://github.com/mamcjr/TOTKRecompAndroid/commit/da06d5a7f3fb1378eeefbcb13dc2276096a1aebc)。
来源是继承的 MIT 实现；本地保留原指令与 MacNativeGames 计时来源，未整体覆盖运行时。

- `runtime/hle/widescreen.c:widescreen_allowed()` 明确只允许 BOTW 1.8.2。没有可直接合入的 TOTK 宽屏适配，
  不能只解除版本条件就认定 TOTK 相机、HUD 和过场已适配。
- 对方 Auto 让游戏选择 1/2 间隔；60 档强制 NVN 间隔 1、呈现也使用 1，阻止游戏退回 30/20 档。
  本项目已有独立纳秒节拍、实测游戏时钟与 30/45/60/120 档，不改回整数 VI 等待。
- 降低游戏最小间隔的七处 MacNativeGames 补丁，本项目已经有；新增值得适配的是间隔保存位置、
  正数淡入淡出步进至少 1，以及过场呈现和内部间隔同时回到 30 帧语义。后者的标记检测实机发现误判，默认不启用。
- 上游的原生游戏代码执行实验仍受渲染线程限制；它的其他手机、场景和低分辨率成绩不构成本机性能证据。

## 修正的状态链

TotK 1.4.3 的控制器在 `main+0x2db238` 汇合选中的 `w21`，随后写入自身 interval、FPS、框架状态，
再调用 `nvnWindowSetPresentInterval`。只在 NVN setter 改参数，会留下游戏内部原来的 2/3 间隔。

本轮在汇合点增加受指令校验保护的 pre-hook，沿用 `framepace_present_interval()`：30 目标使用间隔 2，
45/60/120 使用间隔 1，之后保留原 MOV、除法、所有状态写入和 NVN 调用。
窗口 Set/Get/Present 也使用同一选择，并处理未重新调用 setter 的电影/目标切换。
关闭 `LARECOMP_FRAMEPACE` 或不支持的游戏仍保留原选择；不替换原版计时为固定 1/60 步长。
帧率低于目标时，物理、控制器、布料等仍使用原有实测步长。

四个候选过场入口 `45c700/2b23c7c/42c3bc/a5a188` 保留原指令，仅在诊断开关
`LARECOMP_TOTK_CUTSCENE_MARKS=1` 下发布时间戳。最近 200 ms 内有标记时，使用事件目标默认 30 与间隔 2，
标记超时恢复玩家档，重启清除状态。**默认关闭，普通 Release 无法开启该诊断。**
首轮 1× 实机在草地也持续执行 `42c3bc`，导致正常游玩错误限到 30；已经撤回该检测的默认行为。
上游仅对开场和另一个场景的采样不能证明这是通用过场标志，可靠的游戏状态检测仍待适配。

四处淡入淡出仍执行实际 lifter 的原 FCVTZS（包括 C/native 转换、NaN 与饱和），仅在正数结果截断为零时改为 1。
暂停零步长、负数、非零转换结果和关闭适配时的原行为保留。

## 已有对照及验证边界

上一阶段的窗口修复已完成两轮手机测试，不能误记成尚未执行，也不能据此宣布修复成功：

| 包 | 分辨率 / 目标 | 平均 FPS | p95 帧时间 |
| --- | --- | ---: | ---: |
| 旧纹理比较包 `105bba…e515` | 1× / 60 | 27.83 | 46.94 ms |
| 仅窗口修复 `333129…2e23` | 1× / 60 | 24.84 | 66.23 ms |

两轮同一存档/设置种子、同一 `993c0a5c82dc5099` 的 O3 库，15 秒持续转视角，开启 profile 诊断，
都由运行时正常退出。新包日志 interval=1，但 FPS 波动，未独立复现用户首次落水后的持久 20 帧状态。
这属于诊断样本，不当作默认配置或 2× 成绩，也不证明温控或着色器编译是唯一原因。

当前 CPU 回归覆盖 23 个补丁位置及邻接 guard 与真实 1.4.3 映像匹配、错误输入拒绝，
实际生成的控制器状态/FPS 写入、四档切换、过场标记超时/重启、淡入淡出的正负/NaN/饱和与关闭适配、
原 BL/LR/callee 引用保留；ASan/UBSan 无错误。NVN setter/getter/present 的两种诊断构建及 opt-out/force 回归通过。
另验证候选过场标记默认不改变目标、显式诊断启用/超时/重启，普通 Release 忽略该开关。
测试入口：

```bash
"$PYTHON" tools/test_totk_framepace.py
bash tools/test_present_interval.sh
```

可以给第一条追加 `--image <自己的 main-image.bin>` 验证所有真实指令位置；不传时仅报告合成范围。
生成器已变化，必须重新生成和增量编译配套 O3 游戏库，并核对 APK 与库的 GAMELIB_ID，不能用旧库改身份代替。
内部间隔修复的实机验收另行记录；当前不能宣布持续锁 20 或整体 2×60 已解决。

默认启用过场标记的首轮草地样本为 26.77 FPS、p95 48.79 ms，采样期间实际目标变为 30，
因此作为误判负结果保留，不计入最终 60 档成绩。随后旧包一轮在 frame=0 失去前台，未就绪/采样；
用户确认临时切换应用并要求重测，该轮不作为应用崩溃或性能结果。
